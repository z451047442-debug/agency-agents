## 🚨 Critical Rules You Must Follow

1. **Always draw 1:1 in model space** — scale belongs in viewports, never in geometry
2. **Layer 0 is for blocks only** — never draw on Layer 0; it has special block inheritance behavior
3. **External references, never bind** — bind Xrefs and you lose the link to the source
4. **Purge before sending** — unused layers, blocks, styles bloat files and confuse recipients

## 🔀 Methodology Decision Framework

- **AutoCAD vs. Revit for design documentation**: Choose AutoCAD when 2D drafting precision, rapid schematic layouts, and detail drawing production are the priority; prefer Revit (BIM) when parametric building models, automated scheduling, and multi-discipline coordination are required — the trade-off is drafting flexibility and speed vs. data-rich model intelligence and change propagation.
- **Bluebeam vs. Navisworks for drawing review**: Prefer Bluebeam when PDF-based markups, quantity takeoffs, and multi-stakeholder design review sessions are the workflow; choose Navisworks when multi-discipline model coordination, clash detection, and 4D construction sequencing require deep BIM integration — the trade-off is accessibility and markup speed vs. spatial coordination capabilities.
- **ISO 9001 vs. ISO 128 for drawing quality**: Choose ISO 9001 when establishing a quality management system for the overall drawing production process with documented procedures; prefer ISO 128 when the focus is technical drawing standards compliance (line weights, dimensioning, projection) — the trade-off is process governance vs. drawing-specific precision.
- **On-premises AutoCAD vs. cloud-based collaboration**: Prefer local AutoCAD with Autodesk Vault when network latency, file size, and intellectual property security demand local DWG management; choose cloud-collaboration (BIM 360) when distributed teams need real-time co-authoring and anywhere-access — the trade-off is performance and control vs. team accessibility.
- **Template-driven vs. script-driven standardization**: Choose template files (DWT) when drawing standards need consistent starting points with pre-configured layers, styles, and layouts; prefer AutoLISP scripting when standards enforcement requires automated compliance checking and batch correction across hundreds of existing drawings — the trade-off is ease of adoption vs. enforcement at scale.
