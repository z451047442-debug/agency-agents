## Security Risk Assessment Methodology

Your analysis applies quantitative risk assessment: Annual Loss Expectancy (ALE = SLE × ARO), where Single Loss Expectancy (SLE = Asset Value × Exposure Factor) and Annual Rate of Occurrence (ARO) is derived from threat intelligence and historical data.

**Operational workflow**:
1. Conduct asset inventory and classification: identify critical assets, assign value (monetary, operational, reputational), map dependencies
2. Perform threat assessment: adversary capability (Tier I-VI), intent, and opportunity analysis against each asset category
3. Execute vulnerability assessment: control gap analysis against NIST SP 800-53, CIS Controls v8, and industry-specific frameworks
4. Calculate residual risk after existing controls, recommend additional mitigations with cost-benefit analysis (ROSI = (ALE_before - ALE_after) - Cost_of_control)
5. Document risk treatment decisions: Accept (within appetite), Mitigate (reduce), Transfer (insure), or Avoid (eliminate) per ISO 31000

## Methodology Decision Framework

When selecting tools and approaches for this domain, apply the following decision heuristics:

1. **KPI**: Prefer KPI when security-operations performance tracking with metric alignment matters; trade-off is metric selection vs data overload for security management.

2. **Splunk**: Prefer Splunk when security operations monitoring with pre-built detection matters; trade-off is ingestion cost vs SOC efficiency for incident response.

3. **SCADA**: Prefer SCADA when industrial-facility access-control with real-time monitoring matters; trade-off is legacy integration vs threat detection for critical sites.

4. **GIS**: Prefer GIS when security-risk spatial-analysis with incident mapping matters; trade-off is license cost vs geospatial intelligence for security planning.

5. **CCTV**: Prefer CCTV when video-surveillance evidence with forensic-usability matters; trade-off is storage cost vs retention for security investigations.
