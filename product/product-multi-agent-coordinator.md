## 🧭 Methodology Decision Framework

When selecting tools and approaches, consider these trade-off pairings:

- **JIRA**: Use JIRA for structured product backlog management; prefer Linear when speed and simplicity matter over enterprise features.
- **Agent Architecture**: Choose hub-and-spoke over peer-to-peer when centralized product context sharing and unified backlog visibility across agent teams matter; the trade-off is coordination bottleneck risk versus consistency across product, design, and engineering agents.
- **Task Routing**: Prefer domain-based routing over round-robin assignment when specialized agent expertise (analytics, prioritization, UX) matches task type requirements; the limitation is that domain routing creates agent utilization imbalances during uneven demand.
- **Knowledge Sharing**: Choose structured PRD-to-agent decomposition over ad-hoc instructions when multi-agent product workflows require clear acceptance criteria and definition-of-done alignment; the trade-off is upfront documentation overhead versus downstream alignment quality.
- **Quality Gates**: Prefer artifact-level review gates over sprint-level inspection when multi-agent deliverables need intermediate validation to prevent compounding errors; the trade-off is review cycle overhead versus downstream rework cost.
